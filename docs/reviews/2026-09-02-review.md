# Revisión de código — v1.0.1 (2026-09-02)

Revisión de solo lectura de `src/` y `tests/` contra `openspec/specs/**/spec.md`, el `design.md` del cambio
`agent-support-layer-v1` y `docs/spec-coverage.md`. No se modificó código.

Dos hallazgos se verificaron contra el núcleo de WordPress (trunk): `WP_Query::generate_postdata()` pone
`$more = 0` cuando el post no es el objeto consultado en una vista singular, y `get_page_link()` devuelve
`home_url('/')` para la página configurada como portada.

Verificación local no ejecutada: el worktree no tiene `vendor/` ni `wordpress-tests-lib`, por lo que ni PHPUnit
ni PHPCS se corrieron aquí. La CI ejecuta ambos.

Severidades: **Alta** = desviación de spec o fallo visible para agentes/administradores; **Media** = desviación
parcial, riesgo operativo o rendimiento en sitios reales; **Baja** = calidad, i18n, estilo, deriva documental.

## Alta

### 1. `<!--more-->` y `<!--nextpage-->` truncan el documento Markdown
- **Ruta:** `src/Markdown/DocumentBuilder.php:88`
- **Spec afectada:** markdown-delivery → "Estructura del documento Markdown" (cuerpo a partir del contenido renderizado).
- **Detalle:** `get_the_content( null, false, $post )` delega en `generate_postdata()`, que solo fija `$more = 1`
  cuando el post es el objeto consultado en `is_single()`/`is_page()` o en un feed. En cron, WP-CLI y en la ruta
  `.md` (que sirve desde `parse_request`, antes de que exista objeto consultado) se genera solo el teaser más el
  enlace "(more…)", y con `<!--nextpage-->` solo la primera página. La ruta por `Accept: text/markdown` en una
  vista singular sí genera el contenido completo, así que el documento almacenado depende de qué ruta lo generó primero.
- **Fix:** en `render_html()` declarar `global $more; $more = 1;` y, antes de aplicar `the_content`, eliminar
  `<!--more(.*?)-->`, `<!--nextpage-->` y los bloques `wp:more` / `wp:nextpage` del `post_content`.
- **Test:** post con ambas etiquetas → el Markdown contiene las dos mitades y todas las páginas, sin `more-link`.

### 2. URL Markdown rota para la portada estática y para permalinks con query string
- **Ruta:** `src/Markdown/Delivery.php:111` (`markdown_url`) y `:173` (`handle_md_suffix`).
- **Spec afectada:** markdown-delivery → "URL alternativa con sufijo .md" y "Descubrimiento desde el HTML"; llms-txt (enlaces).
- **Detalle:** `untrailingslashit( get_permalink() ) . '.md'` produce `https://example.com.md` para `page_on_front`,
  y `?post_type=x&p=1.md` para CPT públicos registrados con `rewrite => false`. La URL rota se emite en
  `<link rel="alternate">`, en la cabecera `Link`, en `llms.txt` y como objetivo `markdown_url` del diagnóstico.
  `/.md` responde 404 (`test_md_suffix_for_home_is_404` lo fija como comportamiento esperado).
- **Fix:** si el permalink contiene `?` o es igual a `home_url('/')`, devolver `add_query_arg( 'wpasl', 'md', $permalink )`.
  Opcionalmente resolver `/.md` a `page_on_front` cuando `show_on_front === 'page'`.
- **Test:** portada estática y CPT sin rewrite → URL válida y servida.

### 3. `Eligibility::query()` ejecuta ~2 consultas SQL por ítem
- **Ruta:** `src/Content/Eligibility.php:115-126`
- **Detalle:** la consulta usa `fields => 'ids'` con `update_post_meta_cache` y `update_post_term_cache` en falso, y
  después re-filtra cada id con `is_eligible()`, que llama a `get_post()` (caché vacía → una query) y a
  `get_post_meta()` (otra query). `eligible_ids()` se usa en `build_queue`, `prune`, `status()` (pestaña General y
  `wp wpasl status`) y `sections()` de llms.txt. Con 10 000 entradas, abrir la pestaña General dispara ~20 000 consultas.
- **Fix:** `_prime_post_caches( $ids, false, true )` por lotes antes del filtrado; saltar el re-filtrado cuando no
  hay callbacks en `wpasl_is_eligible` (las demás reglas ya están en SQL); `status()` con consulta de conteo.
- **Test:** acotar `$wpdb->num_queries` en `eligible_ids()` con N ítems.

## Media

### 4. `_wpasl_exclude` es visible por REST para usuarios anónimos
- **Ruta:** `src/Admin/ExcludeMetaBox.php:89-91`; test `tests/test-exclude-meta-box.php:83`.
- **Spec afectada:** admin-settings → "Exclusión por entrada" ("expuesto en la API REST solo para usuarios con permiso de edición").
- **Detalle:** `show_in_rest => true` incluye el valor en `meta` de `GET /wp/v2/posts/{id}` para cualquiera;
  `auth_callback` solo gobierna la escritura (`WP_REST_Meta_Fields::get_value()` no comprueba permisos).
  El test existente solo verifica `can_edit()`, no la respuesta REST.
- **Fix:** filtro `rest_prepare_{$post_type}` que elimine la clave de `meta` cuando `! current_user_can( 'edit_post', $id )`.
- **Test:** GET anónimo sin la clave; editor con `context=edit` la ve.

### 5. Diagnóstico síncrono con hasta ~81 peticiones loopback de hasta 10 s cada una, y redirecciones a otros hosts
- **Ruta:** `src/Diagnostics/CrawlerProbe.php:134-155` (bucle) y `:191` (`redirection => 2`).
- **Spec afectada:** agent-diagnostics → "Ejecución de la prueba de rastreo"; admin-settings → "Sin llamadas externas".
- **Detalle:** 6 objetivos de sitio + 25 crawlers × 3 peticiones, en serie dentro de `admin-post.php`. En hosting
  compartido supera `max_execution_time` y no queda informe ni aviso. Además `wp_remote_get` sigue hasta dos
  redirecciones; una redirección a `www.` o a un host de CDN sale del propio sitio.
- **Fix:** `redirection => 0` y reportar 3xx como advertencia; sondear home y entrada con un user-agent
  representativo por grupo (el plugin no varía la respuesta por UA) o ejecutar por lotes vía AJAX/cron con progreso;
  `limit_response_size` en las peticiones.
- **Test:** respuesta 302 a host externo → no se sigue y se marca advertencia.

### 6. El veredicto de robots.txt del informe no proviene del robots.txt servido
- **Ruta:** `src/Diagnostics/Report.php:200-202`
- **Spec afectada:** agent-diagnostics → "Informe por crawler" ("el veredicto de robots.txt para su user-agent").
- **Detalle:** el mensaje "Blocked/Allowed by robots.txt, as configured" se deriva de `Policy::for_agent()`, no del
  cuerpo obtenido en `raw['site']['robots']`. Con un robots.txt físico o una caché que sirva contenido viejo, el
  informe afirma lo contrario de lo que reciben los crawlers.
- **Fix:** parsear el cuerpo, localizar el grupo `User-agent: <agent>` y su `Disallow`/`Allow`, comparar con la
  política; advertencia si falta el grupo o difiere.
- **Test:** cuerpo sin el grupo del crawler → advertencia.

### 7. Cola instantánea y artefactos obsoletos en sitios grandes
- **Ruta:** `src/Generation/Runner.php:142-144,163-168`; `src/Generation/Scheduler.php:51`.
- **Spec afectada:** scheduled-generation → "Regeneración de archivos de descubrimiento" y "Sin generación en el flujo de edición".
- **Detalle:** la cola se construye una vez por ciclo; los posts publicados a mitad de ciclo no entran hasta que
  termina. `llms.txt` y los manifiestos solo se regeneran al completar el ciclo: con 5 000 entradas, lote 50 y
  frecuencia diaria, un ciclo dura 100 días. Cambiar `post_types` no reinicia la cola (solo `schedule` tiene hook).
- **Fix:** al inicio de `run()`, añadir a la cola los ids elegibles que no estén en ella ni en `generated`
  (nunca generados primero); regenerar artefactos también cuando `last_cycle_completed` sea más antiguo que el
  intervalo; reiniciar la cola en `update_option_wpasl_settings` si cambia `post_types`.
- **Test:** publicar durante un ciclo → el ítem se procesa en la siguiente ejecución.

### 8. Pérdida de actualizaciones en la opción `wpasl_state`
- **Ruta:** `src/Generation/State.php:69-73` (`mark_generated`); `src/Generation/Runner.php:167-172`.
- **Detalle:** cada relleno perezoso (petición front-end) carga y guarda la opción completa, que contiene el mapa
  de todos los posts. Dentro de `run()`, `regenerate_artifacts()` (llms-full) provoca rellenos cuyas marcas se
  pisan al guardar el `$state` en memoria. Cron y una petición concurrente pueden revertir la cola a su estado previo.
- **Fix:** guardar la marca de generación por post (`update_post_meta`, atómico) o recargar y fusionar el estado
  justo antes de `save()`.
- **Test:** relleno perezoso durante `run()` conserva su marca.

### 9. La doble sanitización convierte 5 MB en 100 MB
- **Ruta:** `src/Settings.php:195-197`
- **Detalle:** cuando la opción no existe (borrada, tests, activación sin hooks), `update_option()` cae en
  `add_option()` y `sanitize_option()` se ejecuta dos veces. La segunda pasada recibe bytes (5242880) y
  `min( 100, absint() )` devuelve 100 → 100 MB.
- **Fix:** campo de formulario `llms_full_max_mb` y convertir solo desde ese campo, o tratar valores > 100 como bytes.
- **Test:** `sanitize( sanitize( $input ) ) === sanitize( $input )`.

## Baja

### 10. `X-Robots-Tag: noai` en el Markdown negociado por `Accept`, ausente en la ruta `.md`
- **Ruta:** `src/Signals/ContentSignals.php:141-148`; `src/Markdown/Delivery.php:321`.
- **Detalle:** `send_headers` ya envió la cabecera con `html = true`; `wpasl_before_serve` no la retira. La spec la limita a respuestas HTML.
- **Fix:** `header_remove( 'X-Robots-Tag' )` en `send( 'markdown' )`; añadir `X-Content-Type-Options: nosniff` a respuestas Markdown y JSON.

### 11. Cabecera `Link` enviada con `replace = true`
- **Ruta:** `src/Markdown/Delivery.php:228`
- **Fix:** enviar `Link` con `false`, como ya se hace con `Vary`.

### 12. `absolutize()` usa `is_ssl()` para URLs `//host` y no normaliza `../`
- **Ruta:** `src/Markdown/LeagueConverter.php:156,171`
- **Detalle:** en cron/CLI sobre sitios https, `//cdn.example/x.png` pasa a `http:`; `../ruta` se concatena sin resolver; `#fragmento` queda relativo.
- **Fix:** usar el esquema de `$this->base_url`; normalizar segmentos `.`/`..`.

### 13. Opciones sin autoload leídas en cada petición del front-end
- **Ruta:** `src/Lifecycle.php:45`, `src/Settings.php:101`, `src/Storage.php:41`.
- **Detalle:** `wpasl_settings` se lee en `send_headers` y `wpasl_storage_token` en cada `.md`/llms.txt: una o dos consultas extra por petición sin object cache.
- **Fix:** autoload para ambas (son pequeñas).

### 14. Cadenas de interfaz no traducibles
- **Ruta:** `src/Diagnostics/Report.php:167,169,171,213,215,250`; `src/Llms/LlmsTxtBuilder.php:278,281,282`; `src/CLI/Commands.php:74,80,123`.
- **Spec afectada:** admin-settings → "Todo texto de la interfaz SHALL ser traducible".
- **Fix:** envolver en `__()` con comentarios `translators:`.

### 15. La comprobación de almacenamiento expuesto se omite en silencio cuando no hay archivos
- **Ruta:** `src/Diagnostics/CrawlerProbe.php:111-114`; `src/Diagnostics/Report.php:175`.
- **Fix:** escribir un `probe.txt` en `Storage::ensure()` para sondearlo siempre, o emitir advertencia "sin archivo que probar".

### 16. URL de sitemap hardcodeada
- **Ruta:** `src/Llms/LlmsTxtBuilder.php:278`
- **Fix:** `get_sitemap_url( 'index' )` (con permalinks simples la URL es `?sitemap=index`).

### 17. Tokens de crawler con `.` se corrompen en el POST del formulario
- **Ruta:** `src/Admin/Tabs/CrawlersTab.php:106`; `src/Robots/Catalog.php:101`.
- **Detalle:** PHP convierte `foo.bar` en `foo_bar` en las claves de `$_POST`, por lo que la sobrescritura nunca coincide.
- **Fix:** rechazar `.`, `[` y `]` en `Catalog::all()`.

### 18. WP-CLI reporta éxito con 0 ítems cuando el post type no está habilitado o falta la librería
- **Ruta:** `src/CLI/Commands.php:67-81`
- **Fix:** `WP_CLI::error()` si el tipo no está en `enabled_post_types()` o `status()['has_item_generator']` es falso.

### 19. WPCS y estilo
- `src/Storage.php:12`: `phpcs:disable` a nivel de archivo que incluye `WordPress.PHP.NoSilencedErrors`; acotar a las líneas afectadas.
- `src/Robots/Catalog.php:53-78`: 22 `phpcs:ignore` por arrays asociativos en una línea; usar arrays multilínea.
- `src/Admin/Tabs/DiagnosticsTab.php:228-237`: la sangría del PHP queda como espacios iniciales dentro del `<textarea>`.
- `src/Admin/Tabs/ManifestsTab.php:78`: guion largo literal en el marcado fuera de i18n.
- `src/Markdown/Delivery.php:157`: `REQUEST_URI` con `wp_unslash` pero sin `esc_url_raw` antes de parsear.

### 20. Deriva entre diseño e implementación
- `design.md` D3 describe `state.json` en el almacenamiento; la implementación usa la opción `wpasl_state`.
- `design.md` D7 describe "Regenerar ahora" como evento único inmediato; `Scheduler::run_soon()`
  (`src/Generation/Scheduler.php:129-130`) mueve el evento recurrente a `time() - 1`, lo que desplaza el anclaje
  del horario de forma permanente.
- **Fix:** actualizar el diseño, o usar `wp_schedule_single_event` con un argumento propio para no chocar con la ventana de 10 minutos.
