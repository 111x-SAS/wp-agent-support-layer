Make your site discoverable, readable and operable by AI agents: Markdown delivery, Content Signals, AI crawler rules, llms.txt and agent manifests.

== Description ==

WP Agent Support Layer prepares a WordPress site for AI agents and crawlers ("agent-readiness") without touching your infrastructure. Everything is declarative, read-only for visitors and generated on a schedule so the editing workflow stays untouched.

**Markdown delivery**

* Every published post or page of the enabled content types is available as Markdown: append `.md` to its URL (`/my-post.md`) or request the URL with `Accept: text/markdown`.
* Documents carry YAML front matter (title, URL, type, dates, author, language, description, categories, tags), the title as H1 and the rendered content converted to Markdown with scripts, styles, forms and iframes removed.
* HTML pages announce the Markdown version with `<link rel="alternate" type="text/markdown">` and a `Link` header, and send `Vary: Accept`.
* Documents are pre-generated by WP-Cron in bounded batches and cached on disk, like a sitemap. Saving a post never triggers a conversion.

**Content Signals**

* Declare `search`, `ai-input` and `ai-train` preferences (defaults: yes / yes / no).
* Published as a `Content-Signal` directive in robots.txt, as a `Content-Signal` HTTP header on every public response, optionally as the IETF AIPREF `Content-Usage` header, and as `noai, noimageai` in `X-Robots-Tag` and the robots meta tag when training is not allowed.

**AI crawler rules in robots.txt**

* One `User-agent` group per known AI crawler (GPTBot, ChatGPT-User, OAI-SearchBot, ClaudeBot, Claude-User, Claude-SearchBot, PerplexityBot, Perplexity-User, Google-Extended, Applebot-Extended, CCBot, Bytespider, meta-externalagent, Amazonbot, DuckAssistBot, MistralAI-User and more), grouped as training, AI search and on-demand agents.
* Defaults follow the Content Signals; override any crawler individually. The catalog is extensible with a filter.

**llms.txt**

* `/llms.txt` with the site name, a description, an optional introduction and one section per content type linking to the Markdown version of each item, following llmstxt.org.
* Optional `/llms-full.txt` with the full Markdown of every indexed item, within a configurable size limit.

**Agent manifests**

* `/agent-skills.json`: JSON-LD manifest of the actions an agent can perform without authentication (search, list and read content, Markdown, llms.txt).
* `/wp-json/wpasl/v1/openapi`: OpenAPI 3.1 description of those public REST endpoints.
* `/.well-known/api-catalog`: RFC 9727 catalog pointing to both.

**Diagnostics**

* From Tools → Agent Support Layer, simulate how each AI crawler sees your site: robots.txt verdict, HTTP status, headers, content negotiation, CDN detection, exposed storage. Read-only, with a WAF / rate-limiting checklist and equivalent `curl` commands.

**Privacy**

The plugin never contacts external services and sends no telemetry. The diagnostics only request URLs of your own site from your own server.

**WP-CLI**

`wp wpasl generate [--all] [--batch] [--post-type=<type>]`, `wp wpasl status`, `wp wpasl clear`.

== Installation ==

1. Upload the plugin folder to `/wp-content/plugins/` or install it from the Plugins screen.
2. Activate it. Requires WordPress 7.0+ and PHP 7.4+.
3. Go to Tools → Agent Support Layer. By default posts and pages are enabled, documents regenerate daily, and Content Signals are `search=yes, ai-input=yes, ai-train=no`.
4. Optionally click "Regenerate now" to build the first documents in the background, then open `/llms.txt` and any post with `.md` appended.
5. If your server is nginx, deny direct access to `wp-content/uploads/wp-agent-support-layer/` (see the FAQ).

== Frequently Asked Questions ==

= Does it modify my physical robots.txt? =

No. It only extends the virtual robots.txt WordPress serves. If a physical file exists, the plugin shows the generated rules in the Crawlers tab so you can paste them.

= Does it send data anywhere? =

No. All requests, including diagnostics, target your own site.

= When are the Markdown documents generated? =

On the schedule you choose (hourly, twice daily, daily, weekly) in batches, or manually with "Regenerate now" and WP-CLI. If an agent asks for a document that does not exist yet, it is generated once and stored. Saving a post never triggers a conversion; a post that is unpublished or deleted has its document removed immediately.

= Why does an agent still receive HTML with Accept: text/markdown? =

A page cache or CDN that ignores `Vary: Accept` is serving the cached HTML. Exclude the `.md` URLs from caching or rely on them (they are cached independently), and run the Diagnostics tab to confirm.

= I use Cloudflare "Markdown for Agents". Do I need this? =

Both can convert HTML to Markdown. Keep one: disable the Cloudflare feature to use this plugin's documents (with front matter, llms.txt and manifests), or keep Cloudflare and use this plugin for signals, robots rules, llms.txt and manifests. The Diagnostics tab warns when both are active.

= How do I protect the generated files on nginx? =

Add to your server block: `location ^~ /wp-content/uploads/wp-agent-support-layer/ { deny all; }`. On Apache the plugin ships an `.htaccess`. Documents are only ever served through the plugin, which re-checks that the content is still public.

= Can I exclude a single post? =

Yes. Tick "Exclude from the agent layer" in the post editor sidebar.

= Can I add my own capabilities to agent-skills.json? =

Yes, with the `wpasl_agent_capabilities` filter. Only unauthenticated actions are accepted. See docs/agent-skills.md in the repository.

= Does it work on multisite? =

Yes. Settings and generated files are per site.
